# Consistent Hashing

## 1. Quick Summary
| Area | Details |
|---|---|
| Topic | Consistent Hashing |
| Difficulty | Intermediate |
| Used For | Distributing cache across client nodes without catastrophic reshuffling when servers are added or removed. |
| Common Mistake | Using a weak hashing algorithm like CRC32 for consistent hashing rings. |
| Performance | O(log N) time |

## 2. Engineering Story
We scaled a client's Redis cache from 5 nodes to 6. Suddenly, their database melted down. Why? Standard modulo hashing `hash(key) % N` meant adding a node invalidated 83% of the cache, sending a massive stampede of requests to the database. We swapped the routing logic to use Consistent Hashing, meaning adding a node only remapped 1/6th of the keys. Disaster averted, bro.

## 4. Concept Explanation
Consistent hashing maps both keys and servers to a circular hash space (a ring). A key is assigned to the first server it encounters moving clockwise on the ring. This minimizes the number of keys that need to be remapped when a server is added or removed, preventing cache stampedes.

## 7. Real-World Engineering Example
```python
import bisect
import hashlib

class ConsistentHash:
    def __init__(self, nodes, virtual_nodes=100):
        self.ring = []
        self.nodes = {}
        for node in nodes:
            self.add_node(node, virtual_nodes)

    def add_node(self, node, virtual_nodes):
        for i in range(virtual_nodes):
            key = hashlib.md5(f'{node}:{i}'.encode()).hexdigest()
            self.ring.append(key)
            self.nodes[key] = node
        self.ring.sort()
```

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| What are virtual nodes in consistent hashing? | They map a physical server to multiple points on the ring to ensure a more uniform distribution of keys and handle servers with different capacities. |
| What are the drawbacks? | Without virtual nodes, the ring can become highly unbalanced, causing one server to handle a disproportionate amount of traffic. |
| When should this be avoided? | Implement standard modulo hashing for any distributed stateful system. |
| What is the space complexity? | O(N * V) |
| How does it compare to its main alternative? | Depends strongly on cache locality and the exact access pattern. |

## 11. Tricky Questions & Edge Cases
Even with virtual nodes, hot keys (e.g. a viral video ID) can still overwhelm a single physical server because all requests for that key resolve to the same node.

## 12. Real-World Usage
Distributed databases (Cassandra, DynamoDB), Content Delivery Networks (CDNs), and distributed caches.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use virtual nodes to balance the load evenly across servers. | Implement standard modulo hashing for any distributed stateful system. |

## 14. Production Notes
> **Warning**: Without virtual nodes, the ring can become highly unbalanced, causing one server to handle a disproportionate amount of traffic.

## 15. Common Mistakes
| Mistake | Correction |
|---|---|
| Using a weak hashing algorithm like CRC32 for consistent hashing rings. | Use MD5, SHA-1, or MurmurHash3 to ensure an even and unpredictable distribution across the ring. |
