## 2. The Engineering Story
We integrated with a legacy banking mainframe that took 3 seconds to return a customer balance. The client's mobile app was timing out. We threw an in-memory Hash Map in front of the API, keyed by customer ID, with a 5-minute TTL. The first request took 3 seconds, but the next 10,000 took 1 millisecond. Bro, hash maps save the day when dealing with slow external dependencies.

## 4. How It Works
A Hash Map maps keys to values for highly efficient lookups. It uses a hash function to compute an index into an array of buckets. When multiple keys hash to the same bucket (a collision), it uses techniques like chaining (linked lists) or open addressing (probing) to resolve it.

## 10. Senior Engineering Interview Questions
| Question | Answer |
|---|---|
| What happens when a hash map gets full? | The load factor exceeds a threshold, triggering a 'rehash'. A larger array is allocated, and all existing keys are re-hashed and moved to the new array. |
| What are the drawbacks? | Hash collisions can be exploited maliciously (Hash DoS). Ensure your runtime uses randomized hash seeds to prevent predictable collisions. |
| When should this be avoided? | Use mutable objects as dictionary keys; their hash value will change, leading to silent data loss. |
| What is the space complexity? | O(n) |
| How does it compare to its main alternative? | Depends strongly on cache locality and the exact access pattern. |

## 11. Production Best Practices
If the hash function is poor or malicious users intentionally send keys that cause collisions (Hash DOS), a hash map can degrade to O(N) performance.

## 12. Real-World Applications
Database indexing (Hash Indexes), caching layers (Redis, Memcached), and symbol tables in compilers.
