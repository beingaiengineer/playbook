## 4. Concept Explanation
A Hash Map maps keys to values for highly efficient lookups. It uses a hash function to compute an index into an array of buckets. When multiple keys hash to the same bucket (a collision), it uses techniques like chaining (linked lists) or open addressing (probing) to resolve it.

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| What happens when a hash map gets full? | The load factor exceeds a threshold, triggering a 'rehash'. A larger array is allocated, and all existing keys are re-hashed and moved to the new array. |
| What are the drawbacks? | Hash collisions can be exploited maliciously (Hash DoS). Ensure your runtime uses randomized hash seeds to prevent predictable collisions. |
| When should this be avoided? | Use mutable objects as dictionary keys; their hash value will change, leading to silent data loss. |
| What is the space complexity? | O(n) |

### Advanced Interview Questions

| Question | Answer |
|---|---|
| How do you handle collisions in a Hash Map? | The two main ways are Chaining (using a linked list at each bucket index) and Open Addressing (probing for the next empty slot in the array). |
| What is the load factor of a Hash Map? | It's the ratio of the number of elements to the number of buckets. When it exceeds a certain threshold (often 0.75), the hash map is resized (usually doubled) and all elements are rehashed. |
| Explain how Python's dictionary (or Java's HashMap) mitigates worst-case collision scenarios. | Modern implementations often use a balanced tree (like a Red-Black tree) instead of a linked list for chaining if the bucket gets too full, guaranteeing O(log N) worst-case instead of O(N). |
| Why must keys in a Hash Map be immutable? | If a key's data changes, its hash code changes. If it's already in the map, it will be in the wrong bucket, making it unfindable. |
| How would you design a distributed Hash Map? | You would use Consistent Hashing to distribute keys across multiple nodes, ensuring that adding or removing a node only requires moving a small fraction of the keys. |

### Tricky Edge Cases
- **Hash Denial of Service (DoS):** An attacker can deliberately supply keys that all hash to the same bucket, degrading the server's performance to O(N).
- **Poor Hash Functions:** Using a hash function that doesn't distribute keys uniformly, leading to clustering and performance degradation.


### Real-World Applications (Extended)

- **In-Memory Caches:** Redis and Memcached are essentially giant, distributed Hash Maps. They provide sub-millisecond data retrieval.
- **Database Indexing:** Hash indices are used in databases for lightning-fast equality lookups (e.g., `WHERE id = 5`), though they are useless for range queries (e.g., `WHERE id > 5`).
- **Symbol Tables in Compilers:** When a compiler reads your code, it uses a Hash Map to store variable names, their types, and memory locations.
- **Language Dictionaries:** Python's `dict`, Java's `HashMap`, and JavaScript's `Object` are fundamental language features used in almost every non-trivial script.
- **Set Implementation:** A Hash Set is simply a Hash Map where the values are ignored (or set to a dummy value), using only the keys to ensure uniqueness.
- **Deduplication:** Finding duplicate items in massive datasets often involves hashing items and checking a Hash Map to see if they've been encountered before.
- **Routing Tables:** Some fast-path routing decisions in networking equipment use Hash Maps to quickly determine the output port for a given MAC address.


### Common Production Issues

- **Hash Collisions:** A poorly designed hash function or a malicious attack can cause many keys to map to the same bucket, degrading performance from O(1) to O(N).
- **Resizing Spikes:** When a Hash Map grows beyond its load factor, it must allocate a larger array and rehash all keys. This operation is O(N) and can cause unexpected latency spikes in real-time systems.
- **Memory Overhead:** Hash Maps typically allocate more memory than they strictly need (to maintain a low load factor) and have overhead for bucket structures (like linked list pointers).
- **Iteration Order:** Standard Hash Maps do not guarantee any specific iteration order. Relying on iteration order is a common source of bugs across different environments or language versions.
- **Mutable Keys:** If a key object is mutated after being inserted into the Hash Map, its hash code changes, making it permanently unretrievable.
- **Cache Misses:** Because entries are scattered randomly across the heap based on their hash code, iterating through a Hash Map often results in frequent CPU cache misses compared to array iteration.
