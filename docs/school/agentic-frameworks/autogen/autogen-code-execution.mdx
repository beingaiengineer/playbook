# Code Execution in AutoGen

## 1. Quick Summary
| Area | Details |
|---|---|
| Topic | Code Execution in AutoGen |
| Difficulty | Intermediate |
| Used For | Allowing LLMs to write, run, and debug Python code autonomously. |
| Common Mistake | Running code directly on your host machine without a Docker sandbox, leading to file system corruption or hanging loops. |
| Performance | High execution latency due to Docker container spin-up and teardown. |

## 2. Engineering Story

Bro, LLMs are great at writing code, but they often hallucinate subtle bugs (like a missing import or off-by-one error). Usually, you copy their code, run it, get a traceback, paste the traceback back into the LLM, and say "fix this."
AutoGen says, "Why are you doing this manually?" With AutoGen's Code Execution, the LLM generates a Python script, a `UserProxyAgent` saves it to disk, runs it in a sandboxed Docker container, captures `stdout` and `stderr`, and literally replies to the LLM with the error trace so it can fix itself. It's an autonomous debugging loop.



**FDE Scenario:** Executing LLM-generated code in a client's environment without sandboxing is catastrophic. FDEs use AutoGen's local execution with strict Docker-based isolation to ensure that malicious or buggy code never impacts production.

You don't diffuse a bomb in your living room (Host OS). You put it inside a heavily reinforced, isolated steel chamber (Docker Sandbox) and trigger it remotely. If it blows up (crashes or tries to delete files), it only ruins the chamber, and your living room is completely safe.

## 4. Concept Explanation

AutoGen relies heavily on the `UserProxyAgent` to execute code. When an `AssistantAgent` sends a message containing a Markdown code block (e.g., \`\`\`python ... \`\`\`), the `UserProxyAgent` parses the block, writes it to a temporary `.py` file, and spawns a subprocess to execute it. 
For security, AutoGen provides a `DockerCommandLineCodeExecutor`. It spins up a temporary Docker container, mounts a shared working directory, executes the Python script inside the container, and returns the console output as a chat message.

## 5. Syntax Table
| Concept | Code | Description |
|---|---|---|
| Local Exec (Dangerous) | `LocalCommandLineCodeExecutor(work_dir="output")` | Runs code directly on your machine. |
| Docker Exec (Safe) | `DockerCommandLineCodeExecutor(image="python:3.11")` | Runs code inside a Docker sandbox. |
| Agent Config | `UserProxyAgent(code_execution_config={"executor": executor})` | Attaches the executor to the proxy. |

## 6. Beginner Example

A simple local execution setup (not recommended for production, but good for learning).

```python
import autogen
from autogen.coding import LocalCommandLineCodeExecutor

# 1. Create a local executor (Runs on your host machine!)
local_executor = LocalCommandLineCodeExecutor(
    timeout=60, # Kill script if it hangs for >60s
    work_dir="coding_workspace" # Save scripts here
)

# 2. Attach it to a User Proxy
user_proxy = autogen.UserProxyAgent(
    name="Proxy",
    human_input_mode="NEVER",
    code_execution_config={"executor": local_executor}
)

# 3. Create the Coder
coder = autogen.AssistantAgent(
    name="Coder",
    llm_config={"config_list": [{"model": "gpt-4"}]}
)

# 4. Start the autonomous coding loop
user_proxy.initiate_chat(coder, message="Write a python script to print the first 20 fibonacci numbers.")
```

## 7. Real-World Engineering Example

In production, you MUST use Docker. Here is how you execute code safely in an isolated environment.

```python
import autogen
from autogen.coding.docker_commandline_code_executor import DockerCommandLineCodeExecutor

# 1. Spin up a Docker executor
# It will pull the python:3.11-slim image and run code inside it
docker_executor = DockerCommandLineCodeExecutor(
    image="python:3.11-slim",
    timeout=120,
    work_dir="secure_workspace" # Mounted into the container
)

secure_proxy = autogen.UserProxyAgent(
    name="SecureProxy",
    human_input_mode="NEVER",
    code_execution_config={"executor": docker_executor}
)

data_scientist = autogen.AssistantAgent(
    name="DataScientist",
    llm_config={"config_list": [{"model": "gpt-4"}]}
)

# The agent will write a script, and secure_proxy will run it inside Docker!
with docker_executor: # Ensure the container is cleaned up afterwards
    secure_proxy.initiate_chat(
        data_scientist, 
        message="Write a python script that saves a matplotlib scatter plot to 'plot.png'."
    )
```

## 9. Performance Table

|---|---|---|

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| Why should you never use `use_docker=False` in production? | If the LLM hallucinates or is prompt-injected with `import os; os.system("rm -rf /")`, it will literally wipe your server's hard drive. |
| How does the agent handle missing pip dependencies? | The LLM will receive a `ModuleNotFoundError` from the executor. A smart agent will then generate a new script that runs `!pip install library` or equivalent bash commands to install it dynamically. |
| Can the executor run bash commands? | Yes. The `UserProxyAgent` can execute `sh` or `bash` code blocks, not just Python. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if the code generated by the LLM enters an infinite loop, like `while True: pass`?
By default, the subprocess will hang forever and eat your server's CPU. You MUST define a `timeout` argument on your `CodeExecutor`. If it hits the timeout, AutoGen forcefully kills the subprocess and replies to the LLM: `TimeoutError: Execution took too long`.

## 12. Real-World Usage

- **Automated Pentesting**: An agent writes python scripts to probe an API for SQL injection vulnerabilities. The executor runs the scripts, returns the HTTP responses, and the agent iterates.
- **Data Engineering**: Give the agent a messy CSV file. It writes a pandas script to clean it, execute it, checks the output distribution, and saves a polished parquet file.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use `DockerCommandLineCodeExecutor` in cloud environments | Run local execution on your primary laptop without knowing what the agent is doing |
| Set a strict `timeout=60` | Let scripts run indefinitely |
| Pre-install heavy dependencies (like PyTorch) in the custom Docker Image | Force the agent to run `pip install torch` on every single conversation turn |

## 14. Production Notes
> Production Note:
> If you deploy AutoGen on AWS Fargate or Kubernetes, remember that you are running Docker inside Docker (DinD). Managing nested container permissions can be an infrastructure nightmare. Often, teams prefer the `JupyterKernel` executor connected to a remote JupyterHub server for cloud deployments instead of spawning local DinD instances.

---

### Advanced Code Execution (Jupyter)
1. **Stateful Execution**: The standard Command Line Executor treats every script as isolated. If Script A declares `x = 5`, Script B cannot access `x`.
2. **Jupyter Code Executor**: AutoGen provides a `JupyterCodeExecutor` that maintains state across turns. Just like a Jupyter Notebook, if the agent defines a dataframe in the first message, it can plot that same dataframe in the second message without reloading the CSV!

## 15. Common Mistakes
- **Missing Docker Daemon**: Trying to use `use_docker=True` on a machine that doesn't have Docker Desktop installed or running. The script will crash instantly.
- **File Path Confusion**: The LLM tries to read `/home/user/data.csv`, but because the code is running in Docker, that path doesn't exist. You must mount the correct `work_dir`.
