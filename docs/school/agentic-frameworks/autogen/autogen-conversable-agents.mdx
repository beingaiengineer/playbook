## 2. Engineering Story

Bro, you want to build an agent that reviews pull requests. You start writing a massive `while` loop with `requests.post()` to OpenAI, managing message arrays, and handling role parsing manually. Your code is a spaghetti mess of `messages.append({"role": "user", "content": ...})`.
Instead, you import AutoGen's `ConversableAgent`. This class abstracts the entire chat lifecycle. You just define the agent, call `.generate_reply()`, and the agent automatically handles the message formatting, API calls, tool execution, and token limits.



**FDE Scenario:** When orchestrating multi-agent workflows for client tasks, FDEs rely on AutoGen's ConversableAgents to act as distinct personas (e.g., a dev and a reviewer) that rigorously vet each other's work before a final output is returned.

## 4. Concept Explanation

The `ConversableAgent` is the base class in AutoGen. Almost everything else (`AssistantAgent`, `UserProxyAgent`) inherits from it. It implements the ability to:
1. Receive messages via `receive()`.
2. Keep an internal memory of the conversation history.
3. Generate a response using an LLM, Code Executor, or Human Input.
4. Send messages back via `send()`.

## 6. Beginner Example

Two agents having a completely autonomous conversation, stopping when they say "TERMINATE".

```python
from autogen import ConversableAgent

config = {"config_list": [{"model": "gpt-4o", "api_key": "YOUR_KEY"}]}

# Agent 1
comedian = ConversableAgent(
    name="Comedian",
    system_message="You are a comedian. Tell a joke. End with TERMINATE when the joke is done.",
    llm_config=config,
    is_termination_msg=lambda msg: "TERMINATE" in msg.get("content", "")
)

# Agent 2
audience = ConversableAgent(
    name="Audience",
    system_message="You are the audience. Laugh at the joke.",
    llm_config=config,
)

# Start the chat
audience.initiate_chat(comedian, message="Tell me a joke!")
```

## 7. Real-World Engineering Example

In production, you often need to register custom Python functions (Tools) directly to the ConversableAgent so it can fetch live data.

```python
from autogen import ConversableAgent, register_function

def get_stock_price(ticker: str) -> float:
    # Simulated API call
    return 150.0

analyst = ConversableAgent(
    name="Financial_Analyst",
    system_message="You are a financial analyst. Use tools to get data.",
    llm_config={"config_list": [{"model": "gpt-4"}]}
)

executor = ConversableAgent(
    name="Executor",
    llm_config=False, # Doesn't need an LLM, just runs code
    human_input_mode="NEVER"
)

# Register the tool so the analyst can suggest it, and the executor can run it
register_function(
    get_stock_price,
    caller=analyst,
    executor=executor,
    name="get_stock_price",
    description="Fetches live stock price"
)

executor.initiate_chat(analyst, message="What is the price of AAPL?")
```

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| What is the difference between `AssistantAgent` and `UserProxyAgent`? | They are both `ConversableAgent`s under the hood. `AssistantAgent` defaults to using an LLM and no code execution. `UserProxyAgent` defaults to no LLM, enabling code execution, and asking for human input. |
| How does the agent know when to stop talking? | You must configure `is_termination_msg`. Often, developers use a lambda function to check if the string `"TERMINATE"` is in the message. |
| Can a `ConversableAgent` use local models? | Yes, you can point the `llm_config` to an Ollama or vLLM endpoint that mimics the OpenAI API format. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if both agents have `human_input_mode="ALWAYS"`?
The script will freeze on both ends! One agent will wait for you to type something in the terminal, send it, and then the other agent will immediately prompt you in the terminal again. Always ensure at least one agent is fully autonomous in a back-and-forth loop.

## 12. Real-World Usage

- **Customer Support Router**: A `ConversableAgent` that greets the user, collects their issue, and then hands the session over to a specialized department agent via `initiate_chat`.
- **Automated Code Review**: An agent that receives a GitHub PR diff, analyzes it against the company's style guide, and generates markdown comments.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Set a strict `max_consecutive_auto_reply` limit | Let two agents talk back and forth 5,000 times |
| Use `human_input_mode="TERMINATE"` | Ship `human_input_mode="ALWAYS"` to a serverless cloud |
| Provide highly specific `system_message` strings | Use default personas for complex enterprise tasks |

## 14. Production Notes
> Production Note:
> The `ConversableAgent` logs its conversation history entirely in memory. If your Python process crashes, the conversation is gone. In production, you must hook into the agent's reply mechanisms and write the message payloads to a database (like PostgreSQL or DynamoDB) so you can resume the chat later.

## 17. Advanced Agent Configuration
1. **Multiple LLM Backends**: A `ConversableAgent` can accept a list of models in `config_list`. It will attempt to use the first model (e.g. GPT-4o). If it hits a rate limit or a 500 error, it automatically falls back to the next model in the list (e.g. Gemini 1.5 Pro).
2. **Reply Functions**: You can completely override how an agent thinks by registering a custom reply function using `agent.register_reply()`. This allows you to bypass the LLM entirely for specific message types and insert custom deterministic logic (like looking up an ID in a database before passing it to the LLM).

## 15. Common Mistakes
- **Forgetting `is_termination_msg`**: If you don't tell the agent how to stop, it will hallucinate polite conversation ("You're welcome! Anything else? No, thank you! Goodbye!") until it hits the max round limit.
- **Wrong Role Configuration**: Setting `llm_config=False` on an agent that desperately needs to generate text, causing it to fail silently or prompt the human endlessly.
