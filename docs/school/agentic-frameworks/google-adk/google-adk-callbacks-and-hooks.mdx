## 4. Concept Explanation

Callbacks and hooks in Google ADK allow you to inject Python functions into specific phases of the Agent's execution loop. The core phases are:
- `on_prompt`: Before the request hits Vertex AI.
- `on_response`: After the raw response comes back.
- `before_tool`: Right before a Python tool is executed.
- `after_tool`: Right after a Python tool returns data to the LLM.

These are critical for **Observability** (pushing telemetry to Cloud Logging) and **Security** (intercepting bad tool calls).

## 6. Beginner Example

A simple hook that prints to the console whenever the LLM decides to use a tool.

```python
from google_adk import Agent, EventContext

agent = Agent(model="gemini-1.5-pro", tools=[my_calculator_tool])

# 1. Define the hook function
def log_tool_usage(event: EventContext):
    # event contains metadata about what the LLM is trying to do
    print(f"[AUDIT LOG] LLM requested tool: {event.tool_name}")
    print(f"Arguments: {event.tool_args}")

# 2. Attach the hook to the agent
agent.add_hook("before_tool", log_tool_usage)

# When this runs, the hook will fire automatically
agent.run("Calculate 543 * 992")
```

## 7. Real-World Engineering Example

In enterprise production, hooks are used to send asynchronous metrics to Google Cloud Monitoring so you don't slow down the user's chat response.

```python
import asyncio
from google_adk import Agent, EventContext
from google.cloud import logging

cloud_logger = logging.Client().logger("agent_metrics")

# Use an async hook so we don't block the HTTP response!
async def async_audit_log(event: EventContext):
    # Log token usage to GCP
    if event.phase == "on_response":
        tokens = event.metadata.get("total_tokens")
        cloud_logger.log_struct(
            {"action": "llm_completion", "tokens": tokens, "user": event.session_id}
        )

agent = Agent(model="gemini-1.5-pro")
# Registering the async hook
agent.add_async_hook("on_response", async_audit_log)
```

## 9. Performance Table
| Hook Type | Performance Impact | Use Case |
|---|---|---|
| Synchronous | High (Blocks thread) | Validation, Security blocking |
| Asynchronous | Low (Awaited) | API calls, external DB queries |
| Fire-and-Forget | Zero | Telemetry, Audit Logging |

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| Why use hooks instead of modifying the tool's python code directly? | Separation of concerns. You want to write the tool logic once. Security, logging, and metrics are cross-cutting concerns that should be injected via hooks at the Agent level. |
| Can a hook stop an agent from executing? | Yes. If a `before_tool` hook throws an exception (like a permission denied error), the ADK catches it, cancels the tool execution, and returns the error string to the LLM so it knows it was denied. |
| How do you prevent hooks from slowing down the agent? | By using `async` hooks and dispatching heavy I/O operations (like writing to BigQuery) as background tasks or pushing them to a Pub/Sub queue. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if your `on_response` logging hook throws an exception (e.g., your database is down)? Does the user still get their chat message?
It depends on how the ADK handles hook failures. Typically, if a telemetry hook fails, you want to swallow the error (fail gracefully) so the user still gets their chat response. If a *security* hook fails, you want to hard-crash the request. Always wrap your non-critical hooks in `try/except` blocks.

## 12. Real-World Usage

- **PII Redaction**: An `on_prompt` hook that uses a Regex pattern to replace Social Security Numbers with `[REDACTED]` before the text ever touches the Vertex AI endpoint.
- **Cost Allocation**: An `on_response` hook that grabs the `token_count` from the metadata and writes it to BigQuery, tagged with the `customer_id`, so the finance team can bill customers accurately for AI usage.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use hooks for observability and tracing | Hardcode `print()` statements inside every single tool |
| Make telemetry hooks asynchronous | Block the user waiting for an INSERT query to finish |
| Use `before_tool` for access control | Assume the LLM will obey system prompts to not call restricted tools |

## 14. Production Notes
> Production Note:
> If you are using OpenTelemetry (OTel), hooks are the perfect place to start and stop spans. You start a span in `before_tool`, inject the tool's name as an attribute, and end the span in `after_tool`. This gives you beautiful waterfall charts in Google Cloud Trace showing exactly how much time the LLM spent "thinking" vs how much time it spent executing tools.

### Advanced Hook Patterns
1. **Dynamic Tool Modification**: Advanced hooks can actually mutate the `EventContext`. For example, if the LLM hallucinated a bad parameter for a tool, a `before_tool` hook could detect it, rewrite the parameter to a safe default, and pass the mutated event down the chain without breaking the flow.
2. **Global Application Hooks**: Instead of attaching hooks to a specific `Agent` instance, enterprise ADK setups use Dependency Injection to register global hooks at the application layer. This ensures every single agent spawned in the server automatically inherits the company's security and auditing hooks, preventing junior devs from accidentally bypassing security.

## 15. Common Mistakes
- **Overloading Hooks**: Putting heavy ML models (like a toxicity classifier) synchronously inside an `on_prompt` hook, adding 3 seconds of latency to every chat message.
- **Leaking Secrets**: Logging the raw `EventContext.tool_args` into Cloud Logging when the tool is `change_password(new_password="123")`.
