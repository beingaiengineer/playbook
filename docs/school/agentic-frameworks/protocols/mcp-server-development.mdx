# Developing MCP Servers

## 1. Quick Summary
| Area | Details |
|---|---|
| Topic | MCP Server Development |
| Difficulty | Intermediate |
| Used For | Exposing your custom data or APIs to any AI assistant that supports the MCP protocol. |
| Common Mistake | Using `print()` or `console.log()` for debugging when using the `stdio` transport. It corrupts the JSON-RPC stream! |
| Performance | High. The official FastMCP SDK (Python) makes building servers as fast as writing FastAPI routes. |

Think of building an MCP Server like building an API, but for an LLM instead of a frontend React app.
When you build a REST API, you write endpoints (`/users`, `/posts`) that return JSON for a UI.
When you build an MCP Server, you write Tools (`get_users`, `read_post`) that return JSON for a Large Language Model. The framework handles the JSON-RPC parsing automatically.

## 4. Concept Explanation

To build an MCP server, you don't need to manually parse JSON-RPC strings. Anthropic provides high-level SDKs for Python and TypeScript.
In Python, the standard is the **FastMCP** framework (similar to FastAPI). 
You create an instance of the server, and use decorators like `@mcp.tool()` to expose functions, or `@mcp.resource()` to expose static data. The SDK automatically generates the JSON Schemas from your Python type hints and handles the `stdio` or `SSE` transport layers.

## 5. Syntax Table
| Action | FastMCP Code | Description |
|---|---|---|
| Init Server | `mcp = FastMCP("MyServer")` | Creates the server instance. |
| Expose Tool | `@mcp.tool()` | Exposes an executable function to the LLM. |
| Expose Resource | `@mcp.resource("config://app")` | Exposes read-only data via a URI. |
| Run Server | `mcp.run(transport='stdio')` | Starts listening for JSON-RPC messages. |

## 6. Beginner Example

A complete MCP Server in Python that exposes a simple Calculator tool.

```python
# calculator_mcp.py
# Run with: pip install mcp
from mcp.server.fastmcp import FastMCP

# 1. Initialize the FastMCP server
mcp = FastMCP("CalculatorServer")

# 2. Expose a tool using the decorator
# The docstring and type hints are CRITICAL. They become the JSON Schema for the LLM!
@mcp.tool()
def add_numbers(a: float, b: float) -> float:
    """Adds two numbers together. Use this when the user asks for addition."""
    return a + b

@mcp.tool()
def multiply_numbers(a: float, b: float) -> float:
    """Multiplies two numbers together."""
    return a * b

if __name__ == "__main__":
    # 3. Start the server (defaults to stdio)
    # WARNING: Do not use print() anywhere in this file!
    mcp.run()
```

## 7. Real-World Engineering Example

In production, you often need to expose **Resources** (data the LLM can read directly without calling a tool) and handle asynchronous network calls securely.

```python
import httpx
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("GitHub_Lite_Server")

# 1. Resources use custom URI schemes. 
# The LLM can request "github://readme/owner/repo" to get file contents.
@mcp.resource("github://readme/{owner}/{repo}")
async def get_readme(owner: str, repo: str) -> str:
    """Fetches the README.md for a given public GitHub repository."""
    url = f"https://raw.githubusercontent.com/{owner}/{repo}/main/README.md"
    async with httpx.AsyncClient() as client:
        response = await client.get(url)
        if response.status_code == 200:
            return response.text
        return f"Error: Could not fetch README for {owner}/{repo}"

# 2. Tools are executable actions.
@mcp.tool()
async def get_repo_stars(owner: str, repo: str) -> int:
    """Gets the exact star count of a GitHub repository."""
    url = f"https://api.github.com/repos/{owner}/{repo}"
    async with httpx.AsyncClient() as client:
        response = await client.get(url)
        data = response.json()
        return data.get("stargazers_count", 0)

if __name__ == "__main__":
    mcp.run()
```

## 9. Performance Table
| SDK / Framework | Setup Speed | Best For |
|---|---|---|
| `FastMCP` (Python) | Very Fast | Data science, Python backends, rapid prototyping. |
| `@modelcontextprotocol/sdk` (TS) | Fast | Node.js environments, Web devs. |
| Raw JSON-RPC | Very Slow | Specialized languages (Rust/Go) without an official SDK yet. |

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| Why must you NOT use `print()` in an MCP server? | Because the default transport mechanism is `stdio`. The client (like Claude) reads `stdout` expecting strictly formatted JSON-RPC objects. If it reads a random string like `Debug: starting...`, the JSON parser crashes and the connection drops. |
| How *do* you log debug information? | You must log to `stderr`! Use `sys.stderr.write()` or configure the Python `logging` module to output strictly to `stderr`. |
| What is the difference between `@mcp.resource()` and `@mcp.tool()`? | A Resource provides read-only context (like a file or DB schema) via a URI pattern. A Tool is an action that takes arguments (often mutating state). |

## 11. Tricky Questions & Edge Cases

Bro, what happens if your tool takes 5 minutes to run (like a massive SQL query)?
The MCP protocol itself doesn't have a strict timeout, but the Client (e.g., Cursor or Claude Desktop) usually does (e.g., 60 seconds). If your server blocks for 5 minutes, the client will drop the connection. For heavy tasks, you should return an immediate status (e.g., "Query started with JobID 123") and provide a secondary tool like `check_job_status(job_id)`.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Provide exhaustive python `docstrings` for every tool | Leave docstrings blank |
| Use precise Python type hints (`int`, `List[str]`) | Use `dict` or `Any`, which prevents accurate Schema generation |
| Log all errors gracefully to `stderr` | Let exceptions bubble up and print stack traces to `stdout` |

## 14. Production Notes
> Production Note:
> The easiest way to distribute your Python MCP server is using `uv` (the ultrafast python package manager). If you package your script and upload it to PyPI or GitHub, users can run it seamlessly in their Claude config via `"command": "uvx", "args": ["github:yourname/your-mcp-server"]`. `uvx` creates an isolated ephemeral environment, installs dependencies, and runs the server without messing up the host's global python installation.

## 17. Advanced Development (Prompts & SSE)
1. **Dynamic Prompts**: MCP Servers can also expose `@mcp.prompt()`. This allows the server to dictate *how* the LLM should think. You can define a prompt template like "CodeReviewTemplate" on the server, and the client UI can dynamically load it.
2. **Server-Sent Events (SSE)**: If you want to host an MCP server on the internet (e.g., deploying to Render or Heroku), you cannot use `stdio`. FastMCP allows you to easily bind the server to a FastAPI app and expose `/sse` and `/messages` HTTP endpoints for remote client connections.

## 15. Common Mistakes
- **Hanging Subprocesses**: If your MCP server spawns background threads that don't terminate when the main script receives a SIGTERM, the process will become a zombie on the user's host machine.
- **Assuming the LLM understands URI schemes**: If you define a resource `custom://wiki/{page}`, you MUST provide a tool that allows the LLM to discover what pages exist (e.g. `list_wiki_pages()`). Otherwise, the LLM will never know what URIs to request!
