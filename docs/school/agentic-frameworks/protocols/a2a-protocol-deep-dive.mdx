# Agent-to-Agent (A2A) Protocols

## 1. Quick Summary
| Area | Details |
|---|---|
| Topic | Agent-to-Agent (A2A) Protocols |
| Difficulty | Advanced |
| Used For | Standardizing how independent AI agents discover, negotiate, and communicate with each other over networks. |
| Common Mistake | Assuming A2A communication is just sending plain English prompts between agents via HTTP. |
| Performance | High latency (due to network negotiation), but enables massively scalable decentralized AI swarms. |

## 2. Engineering Story

Bro, imagine you are a senior engineer dealing with troubleshooting a miscommunication between an internal HR agent and a financial agent using the A2A protocol.

Bro, you built a `LegalAgent` in Python. Your friend built an `AccountingAgent` in TypeScript. Your company wants them to collaborate on a merger contract.
How do they talk? You can't just pass Python objects because they are in different languages on different servers. You could write a custom REST API, but what if they need to negotiate continuously? What if 100 other agents want to join?
To solve this, we need an **A2A (Agent-to-Agent) Protocol**. Just like TCP/IP allows computers to talk, and SMTP allows email servers to talk, A2A protocols define a universal language for AI agents to broadcast their capabilities, request data, and reach consensus autonomously across the internet.

Think of A2A protocols like the United Nations.
If a French diplomat and a Japanese diplomat want to negotiate, they don't just yell at each other in their native languages. They use a standardized negotiation protocol (e.g., translators, predefined agendas, formal rules of engagement). 
A2A protocols provide this exact framework: defining how Agent A formally requests help from Agent B, how Agent B proves its identity, and how they format their data exchanges.

## 4. Concept Explanation

Unlike MCP (which connects an Agent to a Tool), A2A protocols connect an **Agent to an Agent**. 
Modern A2A architectures typically require three layers:
1. **Discovery Layer (Registry)**: A directory where agents broadcast "I am a Legal Expert".
2. **Transport Layer**: How the messages move (WebSockets, gRPC, Libp2p).
3. **Semantic Layer (FIPA-ACL)**: The format of the message. Instead of just sending strings, agents send structured intents: `REQUEST`, `PROPOSE`, `ACCEPT`, `INFORM`.

## 5. Syntax Table
| Layer | Concept | Description |
|---|---|---|
| FIPA-ACL | Foundation for Intelligent Physical Agents | The academic gold standard for agent communication languages. |
| Performatives | `INFORM`, `REQUEST`, `CFP` | The "verb" of the message (e.g. CFP = Call for Proposal). |
| Transport | WebSockets / gRPC | Real-time bidirectional streams required for agent debates. |

## 6. Beginner Example

A conceptual representation of how an A2A message is formatted using a FIPA-like JSON structure. Notice it is NOT just a chat prompt; it contains strict metadata.

```json
{
  "performative": "CFP",          // Call For Proposal (Asking for a quote)
  "sender": "agent://sales_agent",
  "receiver": "agent://inventory_agent",
  "reply_with": "req_9921",
  "content": {
    "action": "check_stock",
    "item_id": "SKU-441",
    "quantity": 500
  },
  "ontology": "retail_logistics_v1", // They must agree on the definition of 'item_id'
  "language": "JSON"
}
```
*The inventory agent receives this, processes the JSON, and replies with a `PROPOSE` or `REFUSE` performative.*

## 7. Real-World Engineering Example

In the real world, developers use frameworks like `uAgents` (by Fetch.ai) to build decentralized agents that communicate over standard A2A protocols.

```python
# pip install uagents
from uagents import Agent, Context, Model

# 1. Define the strictly typed data models (Ontology)
class StockRequest(Model):
    item_id: str
    quantity: int

class StockResponse(Model):
    available: bool
    price_per_unit: float

# 2. Create the Agents with cryptographic identities
sales_agent = Agent(name="Sales", seed="sales_recovery_phrase")
inventory_agent = Agent(name="Inventory", seed="inv_recovery_phrase")

# 3. Define how the Inventory Agent handles incoming Requests
@inventory_agent.on_message(model=StockRequest, replies=StockResponse)
async def handle_stock_request(ctx: Context, sender: str, msg: StockRequest):
    ctx.logger.info(f"Received request for {msg.quantity} of {msg.item_id}")
    # Logic to check DB...
    await ctx.send(sender, StockResponse(available=True, price_per_unit=10.50))

# 4. Define how the Sales Agent initiates the conversation
@sales_agent.on_interval(period=10.0)
async def request_stock(ctx: Context):
    # Send an A2A message directly to the Inventory Agent's network address!
    await ctx.send(inventory_agent.address, StockRequest(item_id="SKU-123", quantity=50))
```

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| What is FIPA? | The Foundation for Intelligent Physical Agents. It is an IEEE standard from the 1990s that defines the gold standard for Agent Communication Languages (ACL), relying heavily on performatives (Intents). |
| How do agents agree on data formats? | Through an "Ontology". If Agent A asks for "price", Agent B needs to know if that means USD, Euros, or Crypto. The ontology strictly defines the shared vocabulary. |
| Why use A2A instead of just having one giant LLM orchestrator? | Privacy and Scalability. Two companies cannot share a single orchestrator due to data privacy. A2A allows Company A's agent to securely negotiate with Company B's agent without exposing their internal system prompts or databases. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if a malicious agent joins the network and sends fake data to your agent?
In decentralized A2A networks, Sybil attacks (faking identity) are a massive problem. Modern A2A frameworks use cryptographic keypairs (like Web3 wallets). Every message is signed by the sender's private key. Your agent verifies the signature against a trusted registry to ensure the `BankAgent` is actually owned by the real Bank.

## 12. Real-World Usage

- **Supply Chain Logistics**: A manufacturer's agent broadcasts a need for shipping. 10 different trucking company agents receive the broadcast, calculate their optimal routes, and reply with bids. The manufacturer agent autonomously accepts the lowest bid.
- **Smart Grid Energy Negotiation**: Solar panels running lightweight agents negotiate with neighboring houses to sell excess power locally via A2A micro-transactions.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use strict schema validation (Pydantic models) for message contents | Send unstructured plain-text English between agents |
| Implement timeouts and `REFUSE` fallback logic | Assume an external agent will always reply immediately |
| Authenticate agents via cryptographic signatures | Trust a message just because the sender claims to be `AdminAgent` |

## 14. Production Notes
> Production Note:
> Building true peer-to-peer A2A networks is incredibly difficult due to NAT traversal (firewalls blocking direct connections). In enterprise production, A2A communication is almost always mediated by a centralized Message Broker (like Apache Kafka or RabbitMQ) utilizing topic-based publish/subscribe models, rather than direct IP-to-IP Libp2p connections.

## 17. Advanced Orchestration (Contract Net)
1. **Contract Net Protocol**: This is the most famous A2A interaction pattern. It consists of 4 phases: 1. Manager broadcasts a Call for Proposal (CFP). 2. Contractors evaluate and return Proposals (or Refusals). 3. Manager evaluates all proposals and sends Accept/Reject messages. 4. Accepted contractors execute the work and return the result.
2. **Semantic Routing**: Advanced agents don't rely on hardcoded addresses. They send a message to a semantic router: "I need someone who can translate French". The router analyzes the request embeddings and forwards the message to the optimal translation agent on the network.

## 15. Common Mistakes
- **Assuming LLM Reliability**: Treating the A2A network like a human chatroom where agents can "figure it out". If Agent A hallucinates a malformed JSON payload, Agent B's parser will crash. A2A requires rigid, defensive programming.
- **Infinite Negotiation Loops**: Agent A proposes $10. Agent B counter-proposes $9. Agent A counter-proposes $10. Without a strict `max_negotiation_rounds` limit or a decaying utility function, they will loop forever and consume massive API budgets.

## 18. AI Agent Instructions

| Directive | Instruction | Rationale |
|---|---|---|
| Code Generation | Always include detailed logging and tracing for agent state changes, intermediate tool calls, and LLM thoughts. | Without detailed tracing, debugging silently failing production agents is impossible. |
| Error Handling | Catch exceptions at the tool level and expose them to the trace before bubbling up to the agent. | Tool errors are the most common failure point; hiding them breaks the trace context. |
| Production Patterns | Use structured outputs (like Pydantic models) to enforce strict types between agent nodes or A2A communication. | A2A protocols and agent graphs break when unstructured text is passed instead of typed data. |
| Security | Do not blindly expose internal data through MCP servers without strict access controls and validation. | MCP servers can easily become a massive security risk if they give unrestricted access to databases or APIs. |
