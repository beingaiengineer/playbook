## 4. Concept Explanation

Unlike traditional Python where types are often just "hints" ignored at runtime, **Pydantic enforces types at runtime**. 
Pydantic AI leverages this by enforcing that all inputs to the Agent, all arguments passed to Tools, and the final Output from the LLM strictly adhere to Python type annotations. If the LLM violates these types, Pydantic raises a `ValidationError`.

## 5. Syntax Table

| Concept | Syntax | Description |
|---|---|---|
| Type Hints | `def get_user(id: int) -> str:` | Python's native type hinting |
| Pydantic Model | `class User(BaseModel): age: int` | Strict runtime validation |
| Agent Typing | `Agent[MyDeps, MyResult]` | Generic type parameters for the Agent |

## 6. Beginner Example

Let's see how strict typing prevents bad data.

```python
from pydantic import BaseModel, ValidationError
from pydantic_ai import Agent

class MathResult(BaseModel):
    equation: str
    result: float # STRICTLY A FLOAT

agent = Agent('openai:gpt-4o', result_type=MathResult)

# If the LLM tries to return result="five", Pydantic will catch it!
try:
    response = agent.run_sync("What is 10 divided by 2?")
    print(response.data.result) # 5.0
except ValidationError as e:
    print("The LLM messed up the types!")
```

## 7. Real-World Engineering Example

In a real codebase, you use Generics to strictly type the Agent's dependencies and result type, ensuring your IDE provides perfect autocomplete.

```python
from dataclasses import dataclass
from pydantic import BaseModel
from pydantic_ai import Agent

@dataclass
class UserDeps:
    user_id: int

class Profile(BaseModel):
    name: str
    is_active: bool

# The Agent is strongly typed with its Deps and Result!
# This gives you amazing IDE autocomplete.
agent = Agent[UserDeps, Profile]('openai:gpt-4o', deps_type=UserDeps, result_type=Profile)

# Your IDE knows that `result.data` is exactly a `Profile` object.
```

## 10. Top Interview Questions

| Question | Answer |
|---|---|
| Why is Pydantic so much faster than standard Python validation? | Under the hood, Pydantic V2 is powered by `pydantic-core`, which is completely written in Rust. It performs validation at compiled speeds. |
| Can Pydantic AI handle `Optional` types? | Yes, if you specify `Optional[str]`, Pydantic generates a JSON Schema that allows `null`, teaching the LLM that the field is not required. |
| How do you enforce custom business logic (e.g. age must be > 18)? | You use Pydantic's `@field_validator` on your BaseModel. If the LLM generates an age of 12, the validator throws an error, which can trigger an LLM retry. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if the LLM hallucinates an extra field that isn't in your `BaseModel`?
By default, Pydantic ignores extra fields (they are stripped out silently). If you want to explicitly forbid this (perhaps to save tokens or force strict compliance), you must set `model_config = ConfigDict(extra='forbid')` on your Pydantic model. If the LLM adds an extra field, it will throw a validation error!

- **Financial Systems**: Ensuring transaction amounts are always exact `Decimal` types, not floating-point inaccuracies or strings.

## 13. Best Practices

| DO | DON'T |
|---|---|
| Use specific types (`datetime`, `UUID`, `EmailStr`) | Just use `str` for everything |
| Let your IDE guide you with `Agent[Deps, Result]` | Use `dict` or `Any` to bypass the type checker |
| Add `@field_validator` for deep business logic | Assume the LLM knows your business rules |

## 14. Production Notes

> Production Note:
> Type safety is your last line of defense against prompt injections and LLM hallucinations. If an attacker tricks the LLM into outputting malicious SQL syntax, but your Pydantic model expects an `int`, the attack will fail at the validation layer before it ever reaches your database.

---

### Advanced Type Safety Features
1. **Annotated Types**: You can use `Annotated` from Python's typing module to add massive constraints without writing custom validators. E.g., `age: Annotated[int, Field(ge=18, le=100)]` forces the LLM to provide an integer between 18 and 100.
2. **Generics**: You can build reusable generic Pydantic models (e.g. `class PaginatedResponse[T](BaseModel): items: list[T]`) and pass them dynamically to the LLM agent, allowing for highly modular architecture.

## 15. Common Mistakes

- **Ignoring MyPy/Pyright**: Not running a static type checker on your codebase. If you use Pydantic AI but ignore the squiggly red lines in your IDE, you defeat the purpose.
- **Overly Loose Types**: Using `list[Any]` instead of `list[SpecificModel]`.
