# Pydantic AI Tools and Dependencies

## 1. Quick Summary

| Area | Details |
|---|---|
| Topic | Pydantic AI Tools and Dependencies |
| Difficulty | Intermediate |
| Used For | Allowing your LLM agents to execute real Python code securely. |
| Common Mistake | Using global variables inside tools instead of Dependency Injection. |
| Performance | Fast, but heavily dependent on the external APIs your tools call. |

## 2. Engineering Story

Bro, imagine you are a senior engineer deployed to a client site, and you have to integrate legacy systems. Bro, imagine you built an agent that answers questions about a company's database. You wrote a tool `@agent.tool def query_db(...)` and hardcoded the production database connection string right into the file. It worked perfectly. Then, someone wanted to use the same agent in the staging environment. They had to rewrite the entire file!
Worse, when 100 concurrent users hit the agent, they all shared the exact same database session, causing massive concurrency crashes. By learning about Dependency Injection (`RunContext`), you learned to isolate state per request and pass the database connection dynamically.

## 4. Concept Explanation

An LLM cannot interact with the outside world—it just generates text. **Tools** are Python functions you provide to the LLM so it can fetch data or take actions. 
**Dependencies** (`deps`) are runtime variables (like database connections, HTTP clients, or user IDs) that you inject into those tools when the agent runs, keeping your tools stateless and thread-safe.

## 5. Syntax Table

| Concept | Syntax | Description |
|---|---|---|
| Define Tool | `@agent.tool` | Decorator to register a function as a tool |
| Dependency Context | `ctx: RunContext[MyDeps]` | How a tool accesses injected dependencies |
| Injecting Deps | `agent.run(..., deps=...)` | Passing dependencies at runtime |

## 6. Beginner Example

Let's build an agent with a simple tool. No dependencies yet.

```python
from pydantic_ai import Agent

agent = Agent('openai:gpt-4o')

@agent.tool
def get_weather(location: str) -> str:
    """Gets the current weather for a location."""
    if location == "London":
        return "Rainy, 15C"
    return "Sunny, 25C"

result = agent.run_sync("Do I need an umbrella in London?")
print(result.data) # "Yes, it is currently rainy and 15C in London."
```

## 7. Real-World Engineering Example

Now let's use Dependency Injection. We want the tool to query a database, but the database connection should be passed at runtime.

```python
from dataclasses import dataclass
from pydantic_ai import Agent, RunContext

@dataclass
class MyDeps:
    user_id: int
    db_connection: object # Pretend this is an async asyncpg connection

agent = Agent('openai:gpt-4o', deps_type=MyDeps)

@agent.tool
async def get_user_balance(ctx: RunContext[MyDeps]) -> float:
    """Gets the bank balance for the current user."""
    # We securely access the isolated user_id and db connection!
    query = f"SELECT balance FROM users WHERE id = {ctx.deps.user_id}"
    balance = await ctx.deps.db_connection.execute(query)
    return balance

# At runtime, we inject the dependencies:
deps = MyDeps(user_id=42, db_connection=db)
result = await agent.run("What is my balance?", deps=deps)
```

## 9. Performance Table

| Architecture | Thread Safety | Scalability |
|---|---|---|
| Global Variables in Tools | Extremely Poor | Will crash under load |
| Injected `RunContext` | 100% Safe | Highly Scalable |

## 10. Top Interview Questions

| Question | Answer |
|---|---|
| What is the purpose of `deps_type` in Pydantic AI? | It strongly types the dependency object you plan to pass into your tools, ensuring your IDE and type checker can catch errors if you access `ctx.deps` incorrectly. |
| Why shouldn't you use global variables in agent tools? | Because web servers like FastAPI handle multiple requests concurrently in the same process. Global variables would be shared across users, leading to data leaks. |
| Can a tool return a complex Pydantic object? | Yes, Pydantic AI automatically serializes the returned Pydantic object into JSON before sending it back to the LLM. |

## 11. Tricky Questions & Edge Cases

Bro, what if your tool raises an exception? (e.g. the database times out).
By default, if a tool raises an exception, the agent execution stops and throws a Python error. However, Pydantic AI allows you to raise a special `ModelRetry` exception. If you raise `ModelRetry`, the error message is sent back to the LLM, and the LLM is given another chance to call the tool with different arguments!

## 12. Real-World Usage

- **RAG Systems**: A tool that searches a Vector Database. The vector DB client is passed via dependencies.
- **Action Execution**: A tool that triggers an AWS Lambda function or sends an email via SendGrid.
- **Internal APIs**: Fetching live inventory status from an ERP system.

## 13. Best Practices

| DO | DON'T |
|---|---|
| Provide extremely detailed docstrings for your tools | Assume the LLM knows what the function does based on the name |
| Use `RunContext` for all external state | Hardcode API keys inside the tool function |
| Keep tools focused on doing one single thing | Create a "god tool" that tries to do 10 different things |

## 14. Production Notes

> Production Note:
> The docstring of your Python function is literally injected into the LLM's prompt. If your docstring is confusing or inaccurate, the LLM will hallucinate arguments. Treat tool docstrings as critical prompt engineering.

---

### Advanced Tool Patterns
1. **Dynamic Tool Provisioning**: You don't have to attach all tools to an agent statically. You can dynamically attach tools at runtime based on the user's permission level. For example, an admin user gets the `@agent.tool` for deleting records, while a read-only user does not.
2. **Streaming Tool Outputs**: If a tool takes a long time (like a massive SQL query), the user will stare at a loading spinner. Modern frameworks are starting to support streaming status updates from *inside* the tool back to the client while the tool is executing.

## 15. Common Mistakes

- **Missing Type Hints**: If you write `def search(query):` without type hints (`query: str`), Pydantic cannot generate a JSON Schema, and the tool will fail.
- **Returning Massive Data**: Returning a 10MB JSON string from a tool. The LLM's context window will instantly blow up. Always summarize or truncate tool outputs.
