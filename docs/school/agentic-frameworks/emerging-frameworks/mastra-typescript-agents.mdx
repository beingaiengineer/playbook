## 4. Concept Explanation

Mastra provides three core primitives for TypeScript developers:
1. **Agents**: The core LLM wrapper with a system prompt and memory.
2. **Tools**: Strictly typed TypeScript functions using `zod` schemas. 
3. **Workflows**: State machines (Directed Acyclic Graphs) that orchestrate complex multi-step processes reliably, with built-in telemetry and persistence.

## 6. Beginner Example

Defining a Zod-typed Tool and attaching it to a Mastra Agent.

```typescript
// npm i @mastra/core zod
import { Agent, Tool } from '@mastra/core';
import { z } from 'zod';

// 1. Define a strictly typed Tool using Zod
const weatherTool = new Tool({
  name: 'getWeather',
  description: 'Gets the current weather for a city',
  schema: z.object({
    city: z.string(),
  }),
  execute: async ({ context }) => {
    // Simulated API call
    console.log(`Fetching weather for ${context.city}...`);
    return { temperature: 72, condition: 'Sunny' };
  },
});

// 2. Create the Agent
const weatherAgent = new Agent({
  name: 'WeatherBot',
  instructions: 'You are a helpful assistant. Use tools to answer questions.',
  tools: { weatherTool },
});

// 3. Execute the agent
async function main() {
  const response = await weatherAgent.generate('What is the weather in New York?');
  console.log(response.text); 
}

main();
```

## 7. Real-World Engineering Example

In production, you use Mastra **Workflows** to build resilient, multi-step backend processes (like processing a user upload).

```typescript
import { Workflow, Step } from '@mastra/core';
import { z } from 'zod';

// 1. Define a Step (Node in the graph)
const extractDataStep = new Step({
  id: 'extract_data',
  inputSchema: z.object({ rawText: z.string() }),
  outputSchema: z.object({ summary: z.string(), urgency: z.number() }),
  execute: async ({ context }) => {
    // Call LLM or custom logic here
    return { summary: "Server is down", urgency: 9 };
  }
});

const alertAdminStep = new Step({
  id: 'alert_admin',
  inputSchema: z.object({ urgency: z.number() }),
  execute: async ({ context }) => {
    if (context.urgency > 8) console.log("SENDING PAGERDUTY ALERT!");
    return { success: true };
  }
});

// 2. Build the DAG Workflow
const incidentWorkflow = new Workflow({ name: 'IncidentHandler' });

// 3. Connect the graph!
incidentWorkflow
  .step(extractDataStep)
  .then(alertAdminStep, {
    // Map output of step 1 to input of step 2
    mapInput: (data) => ({ urgency: data.extract_data.urgency }) 
  });

incidentWorkflow.commit();

// 4. Run it
incidentWorkflow.execute({ rawText: "PRODUCTION DB CRASHED!" });
```

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| Why use Mastra instead of LangChain.js? | LangChain.js is often criticized for being a messy port of the Python library, bringing Pythonic object-oriented baggage into JS. Mastra is built specifically for modern TypeScript paradigms (Zod, functional pipelines, Vercel AI SDK). |
| What is the purpose of Zod in Mastra Tools? | LLMs require JSON Schemas to know what arguments to pass to a tool. Zod automatically compiles your TypeScript types into perfect JSON Schemas for the LLM, ensuring you get strictly typed data back. |
| How do Mastra Workflows handle failure? | Workflows act as state machines. Because the execution state is tracked at every step, if a step fails, you can resume the workflow from the failure point without re-running the expensive LLM calls from the beginning. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if the LLM hallucinates arguments that bypass your Zod schema?
Mastra tools intercept the LLM's raw JSON response and run `schema.parse()`. If the LLM sends `{ "city": 123 }` instead of a string, Zod throws a validation error. The framework catches this error and automatically sends it back to the LLM saying, "Error: city must be a string. Fix it and try again." The LLM self-corrects autonomously!

## 12. Real-World Usage

- **Next.js AI Dashboards**: Embedding a Mastra agent directly into a Next.js server action. The user asks for a chart, the agent queries the database tool, and streams React Server Components (RSCs) directly to the frontend.
- **Automated Support Triage**: A Node.js backend cron job that pulls Zendesk tickets, runs them through a Mastra Workflow to classify intent, and routes them to human departments.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use `zod` for everything | Use `any` types in your tools |
| Deploy to Edge or Serverless functions (Vercel) | Rely on long-running stateful memory variables |
| Use Workflows for predictable, multi-step backend processes | Use conversational Agents for strict data transformations |

## 14. Production Notes
> Production Note:
> TypeScript environments (especially Vercel Edge functions) have strict timeout limits (e.g., 10s to 60s). If your Mastra Agent performs deep tool calling loops, it will easily hit these timeouts. In production, you must use streaming responses to keep the HTTP connection alive, or offload the Workflow to a background queue (like Inngest or Upstash).

## 17. Advanced Integrations
1. **Model Agnostic**: Mastra natively supports OpenAI, Anthropic, and Google Gemini via a unified API. You can switch models by simply changing the model string, and Mastra handles translating your Zod tools into the specific format required by that provider.
2. **Evaluation & Telemetry**: Mastra provides built-in evals. You can write unit tests for your agents that run deterministic assertions against non-deterministic LLM outputs to ensure your agent's quality doesn't degrade over time.

## 15. Common Mistakes
- **Ignoring Async/Await**: Forgetting that LLM calls are highly asynchronous network I/O. Failing to properly await agent generation will result in empty UI rendering.
- **Bloated System Prompts**: Writing a 5,000-word instruction block for a simple agent. Keep agents small and orchestrate them via Workflows instead.
