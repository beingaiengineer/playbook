# Agno (Formerly Phidata)

## 1. Quick Summary
| Area | Details |
|---|---|
| Topic | Agno (Formerly Phidata) |
| Difficulty | Beginner |
| Used For | Building agents with long-term memory, built-in RAG (Knowledge), and structured tool usage. |

## 2. Engineering Story

Bro, you built an OpenAI chatbot using LangChain. Now you want it to remember the user's name across sessions. You realize you have to build a PostgreSQL database, write a custom memory manager, handle vector embeddings, and manually inject the history into every prompt. It takes you three days.
Enter **Agno** (formerly known as Phidata). Agno says, "Memory, Knowledge, and Tools shouldn't be hard." You just add `memory=PgMemoryDb(...)` to your Agent definition, and Agno automatically saves the chat history, extracts long-term user preferences, and loads them perfectly on the next turn. You just built a stateful production agent in 5 lines of code.

## 4. Concept Explanation

Agno focuses on the **Stateful Agent** pattern. An Agno `Agent` consists of three pillars:
1. **Memory**: Stores chat history and extracts summarized facts (e.g., "User likes Python"). Often backed by SQLite or PostgreSQL.
2. **Knowledge**: Built-in RAG capabilities. You point Agno to a PDF or a website, and it automatically handles the chunking, embedding, and vector search.
3. **Tools**: Python functions that the agent can execute (e.g., searching the web via DuckDuckGo).

## 6. Beginner Example

A simple agent that searches the web and remembers what you talked about.

```python
# pip install agno duckduckgo-search
from agno.agent import Agent
from agno.tools.duckduckgo import DuckDuckGoTools

# Create a web-searching agent
web_agent = Agent(
    name="Web Helper",
    tools=[DuckDuckGoTools()],
    show_tool_calls=True,
    markdown=True,
)

# The agent will autonomously decide to use the search tool
web_agent.print_response("What is the current stock price of TSLA?", stream=True)
```

## 7. Real-World Engineering Example

In production, you want the Agent to remember the user across sessions using PostgreSQL.

```python
import os
from agno.agent import Agent
from agno.memory.db.postgres import PgMemoryDb
from agno.storage.agent.postgres import PgAgentStorage

db_url = os.environ.get("DATABASE_URL")

# 1. Setup Persistent Storage for the Agent's state
agent_storage = PgAgentStorage(table_name="agent_sessions", db_url=db_url)
# 2. Setup Persistent Memory for the actual chat history and extracted facts
agent_memory = PgMemoryDb(table_name="agent_memory", db_url=db_url)

financial_agent = Agent(
    name="FinanceBot",
    storage=agent_storage,
    memory=agent_memory,
    add_history_to_messages=True, # Automatically injects past context
)

# Start session 1
financial_agent.print_response("Hi, my name is Alex and I have 50 shares of AAPL.")

# Imagine the script restarts here! You can resume the exact session:
# financial_agent = Agent(..., session_id="previous_id")
# financial_agent.print_response("How many shares of AAPL do I have?")
# Output: "You have 50 shares."
```

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| Why did Phidata rebrand to Agno? | To reflect a broader focus beyond just "data" agents, moving towards general-purpose, highly capable AGI-oriented agentic workflows. |
| What makes Agno different from LangChain? | LangChain is a massive, complex toolkit where you have to wire everything together manually. Agno is highly opinionated; it gives you a clean, pre-wired `Agent` class that natively handles memory and knowledge with zero boilerplate. |
| How does Agno handle RAG? | Via `KnowledgeBases`. You provide a data source (PDF, Website, Notion), and Agno automatically chunks it, embeds it, stores it in a Vector DB (like PgVector or Pinecone), and gives the agent a semantic search tool. |

## 11. Tricky Questions & Edge Cases

Bro, what happens if the user talks to the agent for 500 turns? Does Agno send the entire history to OpenAI and bankrupt you?
No. Agno uses memory windowing. By default, it might only inject the last 10 messages into the system prompt. For older context, Agno uses an "Archivist" mechanism to summarize older conversations into bullet points (e.g., "User is a vegan") and injects those summaries instead, saving massive amounts of tokens.

## 12. Real-World Usage

- **Customer Support Bots**: Connect Agno to Zendesk. Give it a `KnowledgeBase` pointing to your company FAQ. It automatically answers questions and remembers customer account details across different tickets.
- **Personalized Tutors**: An agent that teaches you Python, remembers exactly which concepts you struggled with last week, and tests you on them today.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use `PgMemoryDb` for production applications | Rely on the default in-memory SQLite storage for a web backend |
| Enable `markdown=True` and `stream=True` for better UX | Wait 15 seconds for a giant block of text to generate synchronously |
| Give your Agent a specific, narrow persona | Try to build one massive Agno agent that does everything |

## 14. Production Notes
> Production Note:
> Agno relies heavily on PostgreSQL (specifically `pgvector`) for both relational memory storage and vector knowledge storage. In enterprise environments, deploying a managed Postgres database (like AWS RDS or Supabase) with the `pgvector` extension enabled is an absolute prerequisite for scaling Agno agents.

## 17. Advanced Tooling & Structured Output
1. **Structured Output (Pydantic)**: You can force an Agno agent to return strict JSON by setting `response_model=MyPydanticClass`. Agno natively hooks into OpenAI's Structured Outputs feature, guaranteeing that the agent will return parseable JSON instead of conversational text.
2. **Agent Teams**: While Agno shines at single agents, you can pass a list of agents to a central "Team Leader" agent. The leader can delegate tasks to sub-agents (e.g., a Writer and a Researcher) to solve complex workflows, though it is less rigid than AutoGen's GroupChat.

## 15. Common Mistakes
- **Forgetting to load Knowledge**: Defining a `KnowledgeBase` but forgetting to run `knowledge_base.load()`. The agent will search an empty vector database and hallucinate answers.
- **Mixing Session IDs**: If two different users hit your API, you MUST pass a unique `session_id` to the Agent for each user. If you use the same session ID, User B will see User A's chat history!
