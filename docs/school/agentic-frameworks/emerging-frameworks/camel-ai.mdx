# CAMEL AI Framework

## 1. Quick Summary
| Area | Details |
|---|---|
| Topic | CAMEL AI Framework |
| Difficulty | Advanced |
| Used For | Role-playing multi-agent systems that autonomously explore complex tasks. |
| Common Mistake | Giving agents overlapping roles, causing them to agree instantly instead of collaborating to solve a problem. |
| Performance | High token usage due to autonomous back-and-forth communication. |

## 2. Engineering Story

Bro, you want to write a Python game, but you don't want to code. You could prompt ChatGPT 50 times, correcting it when it makes a mistake. 
What if you instead created an AI "Python Programmer" and an AI "Game Designer"? You give them a high-level goal: "Create Flappy Bird."
Instead of you prompting them, **CAMEL** takes over. CAMEL generates 10 specific sub-tasks automatically. Then, the Game Designer prompts the Programmer to write the physics engine. The Programmer writes it and replies. The Game Designer evaluates it and asks for the graphics. They talk to *each other* autonomously until the game is done. You just sit back and watch.

Think of CAMEL like a theatrical improv scene.
You (the user) give the two actors a prompt: "You are a cop and a robber trapped in a bank vault. Go!"
You don't write the script. The actors (Agents) bounce off each other. Actor A says a line, Actor B reacts, Actor A counters. CAMEL provides the structure and the stage for this autonomous role-play to happen without human intervention.

## 4. Concept Explanation

CAMEL stands for **C**ommunicative **A**gents for "**M**ind" **E**xploration of **L**arge Scale Language Model Society.
It pioneered the **Role-Playing Framework**. The core pattern involves:
1. **AI User**: An agent acting as the task assigner (e.g., The Game Designer).
2. **AI Assistant**: An agent acting as the task executor (e.g., The Programmer).
3. **Task Specifier**: A specialized agent that takes your vague idea ("Make a game") and turns it into a highly detailed, concrete prompt.
CAMEL relies heavily on "Inception Prompting" to keep agents strictly in character.

## 5. Syntax Table

## 6. Beginner Example

Setting up a basic Role-Playing session between a Stock Trader and a Python Developer.

```python
# pip install camel-ai
from camel.agents import RolePlaying
from camel.configs import ChatGPTConfig

# Define the roles and the high-level task
task_prompt = "Develop a trading bot for the stock market"

# Initialize the Role-Playing session
role_play_session = RolePlaying(
    assistant_role_name="Python Programmer",
    user_role_name="Stock Trader",
    task_prompt=task_prompt,
    with_task_specify=True, # Auto-expands the vague task into detailed specs
)

# Output the generated detailed task
print(f"Detailed Task: {role_play_session.task_prompt}")

# Start the autonomous conversation loop
chat_turn_limit, n = 10, 0
input_msg = role_play_session.init_chat()

while n < chat_turn_limit:
    n += 1
    # Agents talk to each other!
    assistant_response, user_response = role_play_session.step(input_msg)
    
    print(f"User (Trader):\n {user_response.msg.content}\n")
    print(f"Assistant (Programmer):\n {assistant_response.msg.content}\n")
    
    if assistant_response.terminated:
        break
    input_msg = assistant_response.msg
```

## 7. Real-World Engineering Example

In research and production, CAMEL is often used for massive data synthesis. If you need 10,000 conversational data points to train a new Open-Source LLM, you use CAMEL to generate them autonomously.

```python
from camel.agents import RolePlaying

# You want to generate a synthetic dataset of Medical Triage conversations
roles = [
    ("Triage Nurse", "Panicked Patient"),
    ("Senior Oncologist", "Medical Student"),
    ("Pharmacist", "Elderly Customer")
]

synthetic_dataset = []

for assistant_role, user_role in roles:
    session = RolePlaying(
        assistant_role_name=assistant_role,
        user_role_name=user_role,
        task_prompt="Discuss a medical symptom and determine the next steps.",
        with_task_specify=True
    )
    
    # Run the simulation for 5 turns
    input_msg = session.init_chat()
    for _ in range(5):
        assistant_res, user_res = session.step(input_msg)
        synthetic_dataset.append({
            "user": user_res.msg.content,
            "assistant": assistant_res.msg.content
        })
        input_msg = assistant_res.msg

# You now have highly realistic, specialized conversational data for fine-tuning!
```

## 10. Top Interview Questions
| Question | Answer |
|---|---|
| What is Inception Prompting? | It is CAMEL's core technique of injecting a highly rigid system prompt into the agents before they start talking, forcing them to never break character and always push the task forward. |
| What is the Task Specifier? | Humans are lazy and write terrible, vague prompts ("Make a game"). CAMEL uses a specialized LLM call *before* the role-play starts to expand the vague prompt into a 3-paragraph highly detailed specification. |
| How is CAMEL different from AutoGen? | AutoGen focuses on arbitrary group chats and code execution. CAMEL specifically pioneered the rigid 2-agent (AI User + AI Assistant) role-playing loop for task exploration and synthetic data generation. |

## 11. Tricky Questions & Edge Cases

Bro, what prevents the AI User and AI Assistant from getting stuck in an infinite loop saying "Thank you!" "You're welcome!" "No, thank you!"?
CAMEL's Inception Prompt explicitly forbids conversational pleasantries. The system prompt hardcodes rules like: "Never say thank you. Never apologize. When the task is complete, output `<CAMEL_TASK_DONE>`." The framework parses for that exact token to terminate the loop.

## 12. Real-World Usage

- **Synthetic Data Generation**: Creating massive dialogue datasets to fine-tune open-source models like LLaMA.
- **Automated Research**: Simulating a debate between an "Evolutionary Biologist" and a "Quantum Physicist" to explore novel cross-disciplinary theories.

## 13. Best Practices
| DO | DON'T |
|---|---|
| Use explicit stopping conditions (`<CAMEL_TASK_DONE>`) | Let the agents loop indefinitely |
| Use `with_task_specify=True` | Pass a 3-word prompt directly into the role-playing session |
| Assign highly contrasting roles | Assign "Programmer 1" and "Programmer 2" (they will just echo each other) |

## 14. Production Notes
> Production Note:
> CAMEL is rarely deployed as a user-facing REST API because the role-playing loops take minutes to complete and generate massive amounts of text. It is primarily used as an asynchronous backend job or a local research tool for generating datasets and exploring complex architectures offline.

## 17. Advanced Societal Simulation
1. **Embodied Agents**: CAMEL supports connecting agents to real-world environments. You can create a simulation of a virtual town where agents have roles (Baker, Mayor, Police) and interact with each other and the environment, similar to the famous Stanford Smallville paper.
2. **Multi-Agent Societies**: Beyond just two agents, CAMEL allows for the creation of "Societies" where the framework dynamically spins up new agents (e.g., a "QA Tester") mid-conversation if the original two agents decide they need specialized help.

## 15. Common Mistakes
- **Vague Roles**: Telling the agent it is a "Helper". The Inception Prompt will fail to constrain the agent's behavior. Tell it specifically: "You are a Senior DevOps Engineer with 10 years of Kubernetes experience."
- **Ignoring Token Limits**: Running a 50-turn role-play on GPT-4. Because the entire chat history is sent on every turn, turn 49 will cost 100x more than turn 1.
