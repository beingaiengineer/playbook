## 14. Production Notes

> Production Note:
> A fix is not complete until you can explain how you will detect the bug if it returns. Ensure every bug fix is accompanied by a test case (unit or integration) that explicitly tests for the failure condition.

---

### Advanced Top Debugging Patterns
1. **Binary Search Debugging (Git Bisect)**: When a system suddenly breaks and no one knows why, use `git bisect` to binary search your commit history. It finds the exact commit that introduced the bug in `O(log N)` time.
2. **Rubber Ducking the Call Stack**: Go through the stack trace line by line out loud. Often, engineers skip the middle of the stack trace, assuming the framework is broken, when actually a middleware they wrote modified the request payload.
3. **Isolating State**: Flaky bugs are almost always caused by shared state (global variables, database singletons, or thread locals). Write a test that runs the function 100 times concurrently to prove the race condition.
4. **The "Five Whys" Root Cause Analysis**: Don't just fix the `NullPointerException`. Ask *why* it was null. Ask *why* the upstream system sent null. Ask *why* the contract was violated. Fix the source, not the symptom.

## 15. Common Mistakes

- Missing import-time failures.
