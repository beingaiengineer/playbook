## 2. Engineering Story

A seasoned Java developer transitioned to Python and deployed a microservice with a function that used a mutable list as a default argument `def add_item(item, cache=[])`. After running perfectly in staging, production traffic hit, and users suddenly started seeing each other's private data mixed together. A grueling debugging session revealed the classic Python trap: default arguments are evaluated only once at definition time, creating a shared state across all function calls.

## 17. Advanced Edge Cases and Traps
1. **Late Binding Closures**:
   - Code: `funcs = [lambda: i for i in range(3)]`
   - Trap: Calling `funcs[0]()` returns `2`, not `0`! Python binds closures by reference, not value. By the time you call the lambda, the loop finished and `i` is 2.
   - Fix: Use a default argument: `[lambda i=i: i for i in range(3)]`.
2. **Dictionary Key Overwrites (Hash Collisions)**:
   - Code: `d = {1: "int", True: "bool"}`
   - Trap: `print(d)` outputs `{1: "bool"}`. Wait, what?
   - Fix: In Python, `1 == True` is `True`, and their hashes are identical. Dictionaries overwrite existing keys if they evaluate as equal!
3. **The `+=` operator on Tuples containing Lists**:
   - Code: `t = (1, 2, [3, 4])` then `t[2] += [5, 6]`
   - Trap: It throws a `TypeError` (because tuples are immutable) BUT the list inside actually gets updated to `[3, 4, 5, 6]` anyway. It's the most infamous quirk in Python!
